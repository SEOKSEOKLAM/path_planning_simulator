# Interview Notes

## 1 分鐘項目介紹（口語化）

> 我做了一個基於 Python 的移動機器人路徑規劃仿真系統。這個項目實現了兩種經典的導航算法：A* 和 RRT。A* 是基於栅格地圖的最優搜索算法，用啟發式函數引導搜索方向；RRT 是基於隨機採樣的算法，通過在連續空間中隨機擴展樹來找路徑。我把它們做到一個模塊化的系統裡，可以自動生成障礙物地圖、運行兩種算法做對比，還有可視化輸出。另外我加了一個批量測試框架，可以在不同地圖配置下跑測試、計算指標、導出 CSV 做數據分析。這個過程讓我理解了兩種算法在實際場景中的優劣——A* 能找到更短的路，但 RRT 在複雜環境裡搜索更快。

---

## A* 核心原理怎麼講

面試時可以這樣講：

> A* 的核心是 f(n) = g(n) + h(n)。g(n) 是從起點到當前節點的實際代價，h(n) 是從當前節點到終點的啟發式估計。我用的是歐幾里得距離作為啟發式，因為它滿足"可採納"條件——永遠不高估實際距離，所以能保證找到最短路徑。
>
> 實現上是維護兩個集合：open set（待探索節點）和 closed set（已探索節點）。每次從 open set 裡選 f 值最小的節點擴展，檢查 8 個方向的鄰居是否安全（碰撞檢測），如果鄰居不在 closed set 裡就加入 open set。一直重複，直到找到目標或 open set 為空。
>
> 運動模型用了 8 方向，水平和垂直的代價是 1，對角線是根號 2。碰撞檢測是基於栅格佔用——把障礙物位置轉成栅格坐標，擴展時檢查栅格是否被佔用。還做了機器人半徑的障礙物膨脹，保證路徑的安全距離。

---

## RRT 核心原理怎麼講

> RRT 的思路很直觀：在自由空間裡不斷隨機採樣，從現有的樹找到最近的節點，然後往採樣點方向走一個步長。如果這條邊沒碰到障礙物，就把新節點加進樹裡。循環這個過程，直到樹長到目標點附近。
>
> 幾個關鍵細節：第一是 goal bias，以 5% 的概率直接採樣目標點，這樣不會完全隨機瞎找；第二是 steer，每次只走一個固定步長（2 米），不會直接跳到採樣點；第三是碰撞檢測，會沿著路徑插值檢查每個中間點是否在障礙物圓形範圍內。
>
> RRT 是概率完備的——如果路徑存在，理論上跑足夠久一定能找到。但它的路徑通常不是最優的，會有鋸齒。所以我通常會告訴面試官，實際應用中可以用 RRT 快速找可行解，再做路徑平滑。

## A* 和 RRT 的區別

| 問題 | A* | RRT |
|------|----|-----|
| 什麼地圖？ | 離散栅格地圖 | 連續空間 |
| 能找到最短路徑嗎？ | 能（保證最優） | 不能（次優） |
| 結果穩定嗎？ | 確定性，每次都一樣 | 隨機性，每次不一樣 |
| 適合什麼場景？ | 室內導航、2D栅格 | 機械臂、無人機規劃 |
| 高維空間能用嗎？ | 不行（維度災難） | 可以 |
| 怎麼保證安全？ | 栅格佔用檢查 | 圓形障礙物距離檢查 |

---

## 碰撞檢測怎麼做

> 我實現了兩種碰撞檢測。對於 A* 的栅格地圖，我把連續的障礙物位置轉換成離散的栅格索引，然後對每個栅格位置檢查是否在障礙物的影響範圍內。還加了機器人半徑膨脹——把障礙物在栅格上往外膨脹一圈，這樣規劃出來的路徑自動保證了安全距離。
>
> 對於 RRT 的連續空間，障礙物用圓形建模（每個障礙物有 x, y, radius），碰撞檢測就是計算點到圓心的距離，如果小於半徑之和就判定碰撞。對路徑段做碰撞檢查時，會沿線段插值取樣，檢查每個中間點。

## 批量測試怎麼設計

> 我設計了一個三層的測試框架。第一層是配置——定義多組測試參數：不同地圖大小（50×50、80×80）、不同障礙物數量（15、25、30）、不同隨機種子。第二層是執行——每組配置下分別跑 A* 和 RRT，記錄路徑、運行時間和節點數。第三層是輸出——計算路徑長度、平滑度、安全距離這些指標，導出 CSV，生成對比統計圖。
>
> 這樣做的好處是：不是只跑一次"看起來能跑"，而是系統地評估算法在不同場景下的穩定性。面試官可以看到你不但會寫算法，還知道怎麼驗證它。

---

## 這個項目和機器人測試有什麼關係

> 在真實的機器人系統裡，路徑規劃算法的選擇直接影響導航的效率和安全性。測試工程師需要知道：在什麼地圖規模下算法會失敗？障礙物密度多高時性能會退化？哪個算法更適合當前場景？
>
> 我的批量測試框架就是模擬這個過程。可以把它理解為路徑規劃算法的"單元測試 + 集成測試"——不同地圖配置就是不同的 test case，CSV 輸出就是 test report。在實際工程中，這些數據可以用來做算法選型和參數調優。

## 如果面試官問「是不是抄 PythonRobotics」，怎麼回答

> 我參考了 PythonRobotics 中 A* 和 RRT 的算法流程與可視化思路。PythonRobotics 是一個知名的機器人算法開源教程，它把每個算法寫成獨立的 demo 文件，重點是教學展示。
>
> 但我沒有直接照搬它的項目結構。我把算法流程重新整理成了模塊化的架構：algorithms、maps、evaluation、visualization 四層分離。另外加了三個 PythonRobotics 沒有的東西：一是批量測試框架，可以自動化對比不同場景；二是 CSV 結果導出和 benchmark summary；三是系統性的算法對比可視化，包括左右對比圖和統計圖表。
>
> 可以理解為：算法原理是經典教科書內容（A* 1968 年提出，RRT 1998 年提出），不屬於任何人。我學習了 PythonRobotics 的實現方式，但把它從"教學 demo"改造成了一個更像獨立工程項目的形式。在 MIT 許可下這是完全合規的，我的項目也有獨立的 NOTICE 文件做了歸屬聲明。
